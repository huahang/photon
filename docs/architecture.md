# photon 架构说明

## 设计目标

photon 处理的是**用户不可再生的原始素材**：一次误删或误覆盖，照片就没有了。
因此架构上有三条贯穿始终的原则：

1. **默认不破坏**：任何会改动磁盘的操作，都先生成"计划"，再由用户确认后执行；
   优先复制而非移动，优先移动而非删除。
2. **可解释**：每一步操作都能说清楚"为什么把这个文件放到这里"，便于事后核对。
3. **可中断可重入**：面对几万个文件的大目录，中途退出后重新运行不应造成重复或损坏。

## 分层

自底向上分为四层，上层依赖下层，**下层不得反向依赖上层**：

```
photon/cli/        命令行入口：参数解析、输出格式、退出码
       ↓
photon/organize/   整理策略（规划中）：归档路径规划、去重、执行计划
       ↓
photon/scan/       扫描层：遍历目录，产出 MediaFile 列表
photon/metadata/   元数据层（规划中）：EXIF / QuickTime 拍摄时间、机型、GPS
       ↓
photon/media/      媒体层：类型定义与识别，最底层的共享词汇
```

- `photon/media`：定义 `MediaType` 这一全项目共享的"词汇表"。它不依赖任何其他
  photon 模块，任何模块都可以依赖它。
- `photon/scan`：只负责"有哪些文件"，不解析文件内容。遍历中的单点错误
  （权限不足、坏链接）被跳过而非中断，只有根目录不可用才返回错误。
- `photon/metadata`（规划中）：负责"这个文件是什么时候、用什么设备拍的"。
  这是唯一需要解析文件内容的层，第三方解码库的依赖应收敛在这里。
- `photon/organize`（规划中）：把上面两层的事实转换成"应该放到哪里"的决策，
  产出纯数据的执行计划，本身不碰磁盘。
- `photon/cli`：唯一执行副作用（打印、落盘）的层。

## 错误处理

统一使用 Abseil 的 `absl::Status` / `absl::StatusOr<T>`，不使用 C++ 异常：

- 可预期的失败（路径不存在、格式不支持）→ 返回带中文说明的 `absl::Status`。
- 编程错误（违反前置条件）→ `CHECK` 或断言，让它尽早崩溃。

错误信息面向最终用户，用中文写，并带上出错的具体路径。

## 关于第三方解码库

RAW 解码（LibRaw）、EXIF 解析（Exiv2）、视频容器解析等重型依赖尚未引入。
引入时的顺序偏好：

1. Bazel Central Registry 中已有的模块 → 直接 `bazel_dep`；
2. 否则在 `MODULE.bazel` 中用 `http_archive` + 自写 `BUILD` 文件引入，
   构建文件放在 `third_party/<库名>/`；
3. 避免依赖系统预装库，以保证构建的可复现性。
